# Greenroom

A Chrome extension that puts a small pixel cat in the dead space of video-call waiting rooms. The cat needs nothing from you. When the meeting starts, it leaves without a goodbye screen.

## Design thesis (read before writing any code)

This is an **anti-tamagotchi**. Every implementation decision should be checked against these four rules:

1. **Interruption-safe.** The host can start the meeting at any millisecond. There are no fail states, no progress, no confirmation dialogs, no exit animations longer than 200ms. The despawn fade IS the product thesis.
2. **Zero obligation.** No hunger, no meters, no streaks, no notifications, no persistence, no memory of neglect. If a proposed feature lets the cat be "let down," reject it.
3. **Calm, not engaging.** The user is about to perform (interview, pitch, standup). Animations are slow and soft. Nothing flashes, bounces aggressively, or demands attention. The cat regulates a nervous system; it does not compete for one.
4. **Silent and one-handed.** No audio, ever (the mic is about to go live). All interaction is cursor proximity and single clicks.

When in doubt, the cat does less.

Rules:
- `src/cat/` must never import from `src/extension/`. The cat is a standalone module mounted by either the harness or the content script.
- No frameworks. Vanilla TypeScript + canvas. Vite for dev server and bundling only.
- The harness is a first-class citizen, not scaffolding. All cat behavior is developed and reviewed in the harness before the extension wrapper exists.

## Cat behavior spec (FSM)

States: `idle | wander | sleep | pet | yawn | roll | eat | gone`

| From | To | Trigger |
|---|---|---|
| idle | wander | random timer 2–6s, ~55% chance, picks target x in dead space |
| idle | roll | same decide timer, ~10% chance → belly-up wiggle, 1.6s |
| idle | eat | same decide timer, ~8% chance → head-down nibble, 2.2s |
| wander/roll/eat | idle | arrives at target / timer expires |
| idle | yawn | 15s with no pointer interaction (yawn leads into sleep, 0.9s) |
| yawn | sleep | yawn ends and the pointer still hasn't moved |
| yawn | idle | pointer moved mid-yawn (nap cancelled) |
| sleep | idle | pointer within 60px, or click (plays a stretch animation on wake) |
| any awake | pet | click on cat bbox → squish + 5–6 heart particles, 0.9s |
| pet | idle | timer expires |
| any | gone | detector reports lobby exited → 200ms opacity fade, unmount |

Roll and eat are ambient flavor, not mechanics: no hunger, no bowl, no schedule — rule 2 still holds.

Idle details: blink every 2–5.5s (140ms), tail sway sine ~2.2Hz, eyes track cursor with ±1px pupil offset clamped at 130px range. Sleep details: breathing y-scale ±2.5% at ~1.6Hz, three drifting z's. Wander speed ~42px/s with 4-frame gait.

Stretch goal (only after MVP): if the cursor idles in one spot >8s, the cat walks over and sits near it. Strong "it noticed me" moment, still zero obligation.

## Rendering

- Sprite sheet at 1x pixel art, rendered at integer scale (2x or 3x) with `imageSmoothingEnabled = false`.
- States needing frames: sit (2 idle frames + blink), walk (4 frames), sleep (2 breathing frames), wake-stretch (3 frames), pet-squish (procedural y-scale is fine).
- Cat palette (modeled on the owner's cat): brown/grey mackerel tabby with dark back and forehead stripes, white chest/belly/paws/muzzle, amber eyes, single pink accent (nose / inner ear), bushy raccoon-ringed tail. Soft, low-contrast against light lobby backgrounds. No outlines heavier than 1px.
- Ground shadow: soft ellipse at 7% black, widens when sleeping.

## Extension wrapper (Phase 2)

- Manifest V3. `content_scripts` matched to `*://*.zoom.us/*` and `*://meet.google.com/*`. No background service worker needed for MVP. Permissions: none beyond host matches — keep the install prompt boring.
- Mount inside a **closed shadow DOM** attached to a positioned container so neither side's CSS leaks.
- Detector contract per site: `detect(): { active: boolean, deadSpaceRect: DOMRect | null }`, driven by a `MutationObserver` on a stable ancestor. Zoom: presence of the "Waiting for host to start the meeting" text node. Meet: "Ready to join?" / "Asking to be let in" panel.
- **The exit rule is the most important code in the repo.** When the detector flips to inactive: fade container opacity to 0 over 200ms, then unmount and disconnect everything. No end card, no message, no sound. Debounce detection flapping by 300ms so SPA re-renders don't double-spawn.
- MVP placement: fixed strip along the bottom of the detected dead-space rect. Measuring true empty regions per-site is post-MVP.

## Build phases

1. **Harness + FSM + procedural placeholder cat.** Rectangles are fine. Get state transitions, timers, pointer logic, and the despawn fade feeling right. Debug panel shows current state and elapsed wait.
2. **Real sprites.** Swap procedural drawing for the Aseprite sheet. Tune frame timing by eye in the harness.
3. **Extension wrapper.** Manifest, Zoom detector, shadow DOM mount, exit rule. Test against the real Zoom web lobby.
4. **Meet detector + polish.** Wake-stretch animation, ear twitch, shadow tuning.

## Out of scope — do not build these

- Any persistence (localStorage, sync, naming the cat, stats, a pet log)
- Sound
- Settings page (one toggle in the extension popup at most, post-MVP)
- More than one cat
- Anything that makes the cat "miss you"

The restraint is the design. If a feature idea survives rule 2 above, write it in IDEAS.md instead of building it.

## Conventions for Claude Code sessions

- Harness-first: never develop cat behavior by reloading the extension. If you can't see it in the harness, build the harness page for it first.
- Small modules, no classes unless state genuinely warrants it. The FSM is a plain object + update(dt) loop.
- Every animation timing lives as a named constant at the top of `fsm.ts` (BLINK_MIN, SLEEP_AFTER, EXIT_FADE_MS...) so tuning is one file.
- `EXIT_FADE_MS = 200` is a design decision, not a magic number. Do not "improve" the exit.
- Commit messages: plain declarative, lowercase ("add wake-stretch frames", "debounce zoom detector").
